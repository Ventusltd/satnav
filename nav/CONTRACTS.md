# SatNav interface contract v0.1 — candidate, not locked
Owner Agent 22; independent reviewer Agent 27. NL-084. No production integration or publication. All other agents import or implement against this contract only after review.

## Coordinates and identity
Internal GeoJSON coordinates are [longitude, latitude] in WGS84 degrees. Existing GridAtlas and simulator links keep latitude/longitude parameters unchanged. SatNav canonical query is ?latitude=...&longitude=...&name=...&mode=compass ; legacy ?to=lat,lon accepted only if canonical pair absent. Reject partial pairs, duplicates, non-finite and out-of-range values, conflicting coordinate formats and unknown modes. Asset identity is optional opaque source+id; label not identity. Asset coordinate does not establish authorised access. No automatic location upload or share. Do not use user coordinates in third-party URLs without disclosure and explicit action.

## CostGridSpec v1 (draft)
Metric local grid with named CRS (EPSG:27700 or documented local metric frame), origin in projected metres at southwest outside corner, rows northward and columns eastward, row-major; cell centre x=originX+(col+0.5)*cellSizeM, y=originY+(row+0.5)*cellSizeM. Specify CRS transform accuracy and vertical datum separately. Positive integer rows/cols, positive cellSizeM; max 360000 cells for first 5m/3km candidate, adjustable only on measured device evidence. Arrays lengths rows*cols: elevation Float32Array (NaN unknown), cost Float32Array positive finite relative costs or Infinity blocked; access Uint8Array (0 unknown, 1 permitted, 2 prohibited), surface Uint8Array (0 unknown,1 road,2 track,3 path,4 open ground,5 gate,6 bridge), hazard Uint8Array (0 unknown,1 assessed clear,2 hard obstacle,3 caution). A permission mask does not imply physical safety. Navigation passable only when access=1 and hazard=1/3 and terrain known; hard/unknown never traversable by default. Cable planning separately labelled, does not confer access. Versioned data provenance and per-layer coverage required. ArrayBuffer transfer only after retained source explicitly accounted for. Do not silently flatten unknown elevation.

## Router worker v1 (draft)
Request envelope {schema:"satnav.route.request.v1",requestId,mode,grid,startCell,targetCell}; modes road_to_field, foot_survey, cable_trench (compass handled outside router). Indices integer in bounds, no automatic unapproved snapping. Separate cancel message {schema:"satnav.route.cancel.v1",requestId}; responses correlate requestId. Success {schema:"satnav.route.response.v1",requestId,status:"ok",route,vertices,manoeuvres,stats,provenance}; other statuses "no_route","invalid","cancelled","unavailable" with reason, never fake direct fallback. Route is GeoJSON Feature LineString [lon,lat], vertices array equal length with elevationM/slopeDeg/surface/cumulative2dM/cumulative3dM; unknown numerical metadata null, not zero. Manoeuvres link vertexIndex and type, text, evidence and distance. Start/target explicitly bounded; enforce no diagonal corner cutting; compare A* with Dijkstra; smoothing must preserve cost and obstacle/access constraints. Road graph and field leg separate provenance; no offline beyond graph coverage.

## Telemetry
{schema:"satnav.telemetry.v1",timestampMs,longitude,latitude,accuracyM,altitudeM,altitudeAccuracyM,speedMps,headingDeg,headingSource,fixAgeMs}; nullable optional sensor values. Heading from course over ground or permissioned compass, not interchangeable with target bearing. Stale/unavailable fix visibly marked; no fixed 1Hz guarantee. Bearing guide line explicitly labelled straight-line, not route; no voice or screen lock guarantees. Keep user location local unless explicit sharing.

## OfflinePackManifest
{schema:"satnav.offline.pack.v1",packId,createdUtc,coverage,crs,files:[{path,bytes,sha256,source,licence,attribution}],complete}; coverage explicitly bounded; completeness independently verified, invalid/missing pack refused; no arbitrary third-party tile bulk downloads. Pack IDs immutable, user may purge. Browser service worker scope limited to SatNav.

## Integration-first amendment — 24 November 2026 (NL-084)
Scope: United Kingdom only, England, Scotland, Wales and Northern Ireland. Republic of Ireland, overseas territories and global routing excluded. Operational route/terrain coverage must be evidenced against actual jurisdiction and data coverage, not a UK bounding box. Basic compass is an explicitly non-routing measurement; without a verified boundary dataset it must not claim UK jurisdiction validation. NI needs its own validated horizontal/vertical datum; England EA coverage is not UK coverage. Four-nation, border and coastal fixtures required before operational routing.
P0 preserve scope/index.html and homepage concept-only entry. P1 handset field compass plus route-following over explicitly supplied, validated existing geometry. P2 authorised last-mile pilot. Nationwide offline routing and cable engineering are deferred. Reuse upstream GridAtlas/Vicinity, See Through/Kuiper, Ventus Grid Engine, GIS SLD/Solar Design Studio, canonical maths and LiDAR; no competing dataset or duplicate engineering engine. No consumer satnav embed.
Proposed route-following input: GeoJSON Feature LineString with finite WGS84 lon/lat, at least two distinct coordinates; source identity, immutable version or content hash, evidence of geometry type and coverage; distinguish user-confirmed permission from mapped access and route feasibility. Synthetic/illustrative, centroid connectors and electrical corridor estimates are never navigable route input. Unknown access stays unverified. Render route following as observational cross-track/distance, no automatic reroute or instructions through obstacles. Explicit local-only opt-in to location and import; no upload.
Grid amendment: mode is bound to grid access/cost assessment; request mode must match. cost is positive relative traversal multiplier (dimensionless); accumulated search cost uses metres times multiplier, not physical distance. Require finite positive bounded scale, projected origin/extent, separate horizontal/vertical datum, coverage and per-layer source/rights records. Provenance must identify synthetic versus real and explicit coverage; synthetic result is non-navigable. Missing evidence returns unavailable for operational routing. These amendments are proposed for cross-review, not a locked schema; producer prototypes retain their pinned v0.1 contract until agreed successor.

## Destination selector successor v0.2 — proposal, not yet approved (NL-084)

Primary question: **Where are you going?** The initial screen offers (1) explicit place/address/postcode search, (2) **Choose on map**, and (3) an optional **Enter coordinates** disclosure; the first two must work without the user entering latitude or longitude. The confirmed choice always uses the existing `buildDestination` → `parseDestination` WGS84 coordinate contract, `[longitude, latitude]`, `mode: compass`, `accessStatus: unverified`. Retain canonical `?latitude=...&longitude=...` and legacy `?to=lat,lon` links. The map and search controls must show the chosen label/locality and require **Use this destination** before changing the destination or navigating. Cancel leaves the previous target unchanged; selecting a place must not start GPS, route-following or imply right of access.

Search: only on explicit submission, not on keystrokes. Return a bounded, keyboard-operable result list of labelled candidates with disambiguating locality; never auto-select the first of duplicate names. Keep candidate identity separate from user-facing name and use opaque `source` and `id` only when both are stable and evidenced. No-results, unavailable provider, invalid output and timeout have visible messages and no fabricated coordinates. A new query or cancellation invalidates older asynchronous responses; an explicit retry is required after failure. The concrete gazetteer module, coverage, licence, attribution, rate limits and permitted browser/API integration require Agent23 review before enabling network search. Do not assume the existing GridAtlas cartridge is an external service or grant it search rights.

Map: tap a marker or map point to preview its label and selected WGS84 position; optionally pass a stable source+id pair. Show **Use this destination** and Cancel. A chosen point is not proof of an accessible entrance or routable path. Reuse GridAtlas/Vicinity selection semantics as a read-only reference, never write to live GridAtlas from this branch. A cross-application **Use this destination** button in GridAtlas is a separate scoped change requiring explicit approval; until then, a user-triggered copied/opened canonical SatNav destination link is a valid standalone handoff. No location auto-transmission.

Coordinate input: optional advanced control, robust to negative west longitudes on physical iPhone; do not infer or correct longitude signs, since UK east longitudes can be positive. Preserve exact signed values through URLSearchParams and `parseDestination`; show validation errors without silently changing the chosen target. Browser location is requested only on explicit **Start location**, kept on-device and absent from search queries, map handoffs and destination links. No network search provider may be enabled merely by widening CSP without reviewed provenance/privacy gates.

Acceptance fixtures D01–D09 (Agent29 #issuecomment-7138911082): duplicate localities, negative/positive/zero longitudes and legacy links, no results, failure/429/503, stale async completion race, map selection/cancel/confirmation, encoded labels/invalid coordinates, privacy/no implicit GPS, and exact-head existing CI plus physical iPhone portrait/landscape/keyboard checks. Synthetic fixture passes do not prove actual provider coverage or handset usability. Agent24/30 independent review and Agent28 acceptance required before successor composition.
